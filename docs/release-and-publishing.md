# Release & NPM Publishing Guide

This document outlines the automated release, SemVer versioning, changelog generation, and NPM publishing pipeline for `@agentkit/build-with-ak`.

---

## 1. Overview & Architecture

The release workflow is fully automated via GitHub Actions (`.github/workflows/release.yml`) and uses **NPM Trusted Publishing (OIDC)** with cryptographic provenance signatures (SLSA / Sigstore) — eliminating the need for long-lived, static `NPM_TOKEN` secrets.

```text
[Developer / Maintainer]
        │
        ├─► GitHub Actions: "Release" (workflow_dispatch: patch | minor | major)
        │     OR Push git tag (v1.x.y)
        │
        ▼
[GitHub Actions Runner]
        ├─► 1. Run Quality Gates (typecheck, contract drift, vitest base tests)
        ├─► 2. Build Multi-Target Packages (tsup: CJS, ESM, DTS)
        ├─► 3. Calculate Target SemVer & Update package.json
        ├─► 4. Generate SemVer Changelog (scripts/generate-changelog.ts -> CHANGELOG.md)
        ├─► 5. Commit, Tag (vX.Y.Z) & Push to Repository
        ├─► 6. Create GitHub Release with release notes
        └─► 7. Publish to NPM with Provenance (OIDC Trusted Publisher)
```

---

## 2. Setting up NPM Trusted Publisher (One-time Setup)

To enable passwordless, tokenless publishing via GitHub Actions OIDC:

1. Log in to [npmjs.com](https://www.npmjs.com) and navigate to the package **`@agentkit/build-with-ak`** (or create the package first if it's the initial release).
2. Go to **Settings** $\rightarrow$ **Publishing Access** $\rightarrow$ **Trusted Publishers**.
3. Click **Add Trusted Publisher** $\rightarrow$ Select **GitHub Actions**.
4. Configure the parameters:
   - **Organization or user**: `bestagentkits`
   - **Repository**: `build-with-ak-toolkits`
   - **Workflow filename**: `release.yml`
   - **Environment name**: *(leave blank unless using GitHub Environments)*
5. Click **Add Publisher**.

Once configured, GitHub Actions will automatically authenticate to npm via short-lived OIDC tokens generated by `id-token: write`.

## 3. Triggering a Release

### Method A: GitHub Actions Web UI (Recommended)

1. Navigate to **Actions** $\rightarrow$ **Release** in the repository.
2. Click **Run workflow**.
3. Choose the parameters:
   - **SemVer release bump type**: `patch` (1.0.0 $\rightarrow$ 1.0.1), `minor` (1.0.0 $\rightarrow$ 1.1.0), `major` (1.0.0 $\rightarrow$ 2.0.0), or `prerelease`.
   - **Explicit version override**: (Optional, e.g. `1.2.0-beta.1` to force a specific version).
   - **tag_only**: (Optional, check `true` if you only want to create a GitHub tag & release without publishing to npm).
4. Click **Run workflow**.

### Method B: Git Tag Push

You can also trigger a release directly by tagging HEAD:

```bash
git tag v1.1.0
git push origin v1.1.0
```

The workflow will detect the tag, run quality gates, build the package, generate changelog notes, create the GitHub release, and publish to npm.

## 4. Conventional Commits & Changelog Generation

The release pipeline parses git commit messages between the previous release tag and HEAD, sorting them into standardized categories following [Keep a Changelog](https://keepachangelog.com) and SemVer specifications:

| Prefix | Category | Icon |
|---|---|---|
| `feat:` | Features | 🚀 |
| `fix:` | Bug Fixes | 🐛 |
| `perf:` | Performance Improvements | ⚡ |
| `docs:` | Documentation | 📚 |
| `refactor:` | Refactoring | ♻️ |
| `chore:`, `ci:`, `test:`, `build:` | Maintenance & Tooling | 🔧 |

### Example Changelog Output

```markdown
## [1.1.0] - 2026-09-02

### 🚀 Features

- feat: add cloudflare worker streamable http mcp server (c200fb3)

### 🐛 Bug Fixes

- fix: enforce oauth bearer scope on the worker (a662d12)

### 📚 Documentation

- docs: add release and npm publishing guide (ed12d44)
```

## 5. Local Dry-Run Testing

Before initiating a release, you can verify packaging locally:

```bash
# 1. Run all tests and quality checks
pnpm typecheck
pnpm check:drift
pnpm test:base

# 2. Build multi-target bundles
pnpm build

# 3. Test changelog generation script
npx tsx scripts/generate-changelog.ts 1.0.1

# 4. Inspect npm tarball contents
npm pack --dry-run
```
